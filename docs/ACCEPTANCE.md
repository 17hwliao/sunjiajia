# 审计与结算准则

每项按 0–5 分评估，总分 25 分。

| 维度 | 审核重点 |
|---|---|
| 功能正确性 | 是否满足全部验收标准，失败路径是否可控 |
| 可验证性 | 是否提供可重复运行的测试与清晰输出 |
| 架构边界 | 是否遵守模块职责、接口合约与任务范围 |
| 安全与隐私 | 是否避免密钥泄露、越权 Tool、隐私数据外发 |
| 可维护性 | 命名、错误处理、日志、配置和回滚是否充分 |

## 结算规则

- `ACCEPTED`：22–25 分，且无 P0/P1 问题。
- `CONDITIONAL`：18–21 分，无 P0 问题；可在后续任务补足。
- `RETURNED`：低于 18 分，或存在 P1 问题。
- `BLOCKED`：依赖、权限或外部服务缺失，无法作出有效验收。

P0 包括：泄露密钥、未授权外发个人数据、可执行任意系统命令、破坏用户文件。P1 包括：核心功能失效、未经确认的外部副作用、无法运行或无法回滚。
