# TASK-002：实现多子 Agent 任务编排骨架

- 状态：`READY`
- 优先级：`P0`
- 负责人：`执事 AI（可委派子 Agent）`
- 依赖：`无`

## 目标

实现一个可审计、可限流的多子 Agent 编排能力：执事 AI 能把互不冲突的开发任务拆解、并发分派、汇总证据，并把需要人工决策或发生冲突的事项明确上报。

## 角色与职责

- `Planner`：读取任务卡，生成带依赖关系的子任务图（DAG）和文件所有权声明；不修改产品代码。
- `Implementer`：每个可并发子任务由一个独立子 Agent 在独立分支或 worktree 中实现；不得触碰其他子任务声明拥有的文件。
- `Tester`：独立复核运行命令、测试结果和复现步骤；不修改功能实现。
- `SecurityReviewer`：检查密钥、个人数据外发、任意命令执行、危险文件操作和越权工具调用。
- `Integrator`：仅在依赖完成、文件所有权无冲突、测试与安全复核均通过时生成候选合并方案；不得自行推送远程或覆盖他人改动。

## 范围

- 创建一个 .NET 8 编排项目（项目命名可自行选择），提供 CLI 或等价的最小可演示入口。
- 定义可 JSON 序列化的 `WorkItem`、`Dependency`、`AgentRole`、`DispatchPlan`、`AgentEvidence`、`ReviewFinding` 和 `RunSummary` 合约。
- 输入一组任务及依赖关系后，构建 DAG，识别循环依赖，并只同时调度依赖已满足的任务。
- 支持可配置的最大并发数，默认值不超过 `3`；实现取消、超时和失败传播。
- 生成每次运行的审计记录：任务 ID、角色、开始/结束时间、输入摘要、输出摘要、关联分支/worktree（如有）、测试证据、风险发现、状态和原因。
- 实现一个不调用真实模型、网络、命令行或 Git 写操作的 `FakeAgentRunner`，用于可靠单元测试与演示。
- 为未来接入执事 AI 提供明确的 `IAgentRunner` 适配器边界；本任务不接入任何具体模型服务。
- 在 README 或专门设计文档中说明如何并发执行以下彼此独立的任务：动作映射、RAG 存储层、语音输入层；以及它们如何在公共合约任务完成后汇合。

## 安全与协作约束

- 不得在子 Agent prompt、日志或审计记录中写入 API Key、访问令牌、用户原文记忆、音频或绝对个人目录。
- 不得默认授权浏览器、文件写入、鼠标键盘、进程执行、网络请求或 MCP 工具；这些能力必须通过未来的显式审批接口接入。
- 不得自动 `push`、`merge`、`rebase`、覆盖工作区或删除文件。
- 子 Agent 最多一层委派；必须遵守并发上限，避免无限递归或失控资源占用。
- 文件所有权重叠、依赖循环、测试失败或安全 P0/P1 发现必须使任务进入 `BLOCKED` 或 `RETURNED`，不能静默继续合并。

## 不包含

- 不调用真实的远程/本地大模型。
- 不实现桌宠、RAG、ASR、TTS、浏览器或系统自动化功能。
- 不创建模型文件、向量库、用户记忆或任何真实外部账号配置。
- 不改动现有桌宠 EXE 或其资源。

## 验收标准

- [ ] `dotnet test` 成功。
- [ ] 至少有一个测试验证：三个无依赖任务在并发上限为 `2` 时被分批调度，且从不超过上限。
- [ ] 至少有一个测试验证：有依赖的任务只能在其前置任务成功后开始。
- [ ] 至少有一个测试验证：循环依赖被明确拒绝，并携带可读原因。
- [ ] 至少有一个测试验证：任务失败、取消、超时和文件所有权冲突不会产生“可合并”结论。
- [ ] 审计记录可 JSON 序列化，且测试确认不含密钥或用户内容字段。
- [ ] 默认实现不发起网络请求、不执行系统命令、不操作真实 Git worktree，也不向远程仓库推送。
- [ ] 演示命令能输出可读的 Dispatch Plan 与 Run Summary。

## 交付要求

提交说明必须包括：运行与测试命令、并发调度示例、架构边界、失败处理说明、已知限制、回滚方式，以及由哪些子 Agent 分别完成了什么。

## 审计评分重点

- 是否真的实现了 DAG、并发上限和失败阻断，而不是只用顺序队列模拟。
- 是否把真实模型/系统工具置于显式适配器和审批边界之后。
- 是否能让后续的动作、RAG、语音任务安全并发且避免文件冲突。
